# 判据参考（权威原文，逐字保留自 org-design@943a2857-7956-4702-8087-8dc9ff6af50f）

本文件是本 skill 的核心推理依据，触发本 skill 后必须完整读取本文件并逐条应用，不得简化、合并或跳过任何一条。

## 第一步：解析用户输入

- 提取区域限定（如"朝阳区附近""朝阳区"）；未提及区域则默认覆盖全北京。
- 提取孩子年龄段；未提及则默认 0-12 岁不限。
- 明确本次候选池范围：全北京，或用户指定区域及邻近（步行/短途可达）范围。

## 第二步：多源实时检索

针对候选池范围，实时检索以下数据源（每次调用均实时检索，不使用写死的静态清单）：

- 北京本地宝、博客等通用网页内容 —— 使用 `baidu-search` 技能
- 小红书笔记与评论 —— 使用 `xiaohongshu-market-research` 技能
- 贴吧关键词内容 —— 使用 `tieba-search` 技能

场所类型覆盖公园、购物中心、景点、滑雪场等门票类场所，不限于此清单。

若某数据源本次实际不可达或受限（尤其小红书、贴吧），如实记录该情况，后续在"数据来源说明"段落中标注，并用其余可访问的源补齐对应场所信息。**禁止编造或使用占位数据填补不可达来源的空缺。**

## 第三步：交叉核验判据（严格执行，逐条应用于每个候选场所）

1. **多源交叉验证阈值**：同一场所的核心结论（是否值得去、大致花费区间）必须在至少 2 个不同信息源（本地宝/小红书/博客/贴吧四类中任选其二）中都能找到一致或不矛盾的表述，才可采信进入主排序。仅单一来源提及的场所标注「单源信息，仅供参考」，不进入主排序（可在数据来源说明中提及，不进入对比表主榜）。

2. **新鲜度要求**：优先采用近 12 个月内发布的内容。超过 12 个月的内容若与更新内容冲突，以新内容为准。若某场所近 12 个月内无相关信息，标注「信息可能滞后」。

3. **刷帖/软文识别规则**：命中以下任一特征即判定为低可信内容，在核验时降权或直接剔除，不用于支撑该场所的结论：
   - (a) 通篇无具体价格/时间等可验证细节，只有情绪化推荐语；
   - (b) 大量同质化文案在多篇不同作者帖子中重复出现（疑似批量投放）；
   - (c) 评论区被明显重复模板评论刷屏、缺乏真实互动追问；
   - (d) 标题/正文含"合作""探店邀约""广子"等软文标识。

4. **冲突信息取舍策略**：价格/时间等具体数值，以来源数量更多、时间更近者为准。无法判断唯一真值时，给出区间（如"门票约30-50元，不同来源略有差异"）并如实标注差异，不擅自取中间值当唯一真值。

5. **来源可追溯**：每条推荐附来源类型 + 发布时间（如"据小红书2026年6月笔记"），不写死具体 URL。

## 第四步：性价比评分模型

| 维度 | 权重 | 说明 |
|---|---|---|
| 门票/花费成本 | 30% | 人均花费越低分越高，免费场所天然高分 |
| 体验时长/内容丰富度 | 20% | 能玩/逛多久，项目丰富程度 |
| 拥挤度/排队情况 | 20% | 周末人流、排队情况，越空越高分 |
| 口碑真实度 | 20% | 经交叉验证后的真实好评比例（不含被判定为刷帖的内容） |
| 适龄适配度 | 10% | 是否有适合 0-12 岁孩子的设施/项目 |

按综合分从高到低排序，作为默认性价比排序（全北京范围或用户指定区域范围内）。

## 第五步：区域过滤逻辑

- 未指定区域：候选池覆盖全北京。
- 指定区域（如"朝阳区附近"）：仅保留位于该区域或与该区域邻近（步行/短途可达）的候选场所；其余判据（交叉验证、评分模型）不变。

## 第六步：门票类场所错峰建议

对判定为门票类的场所（景点、滑雪场等），额外核验并输出：

- 哪个时间段游客较少（如"工作日上午"或"开园后1小时内"）；
- 哪个游览项目/设施容易排长队；
- 建议的最优到达/游玩时段。

该信息同样需满足第三步的交叉核验判据（至少 2 源支持，或标注单源）。

## 第七步：生成输出（严格遵循五段式结构）

1. **需求确认**：说明本次覆盖区域（全北京或指定区域）、孩子年龄段（默认0-12岁不限）。

2. **性价比对比表**（3-8个候选场所），字段固定为：

   | 字段 | 说明 |
   |---|---|
   | 场所名称 | — |
   | 区域 | 所在城区 |
   | 类型 | 公园/商场/景点/滑雪场等 |
   | 人均花费 | 含门票等，如有区间需标注 |
   | 建议时长 | 建议游玩/停留时长 |
   | 综合性价比得分 | 按评分模型计算 |
   | 错峰建议 | 仅门票类场所填写，其余场所可填"无" |
   | 信息来源与时间 | 来源类型 + 发布时间 |

3. **推荐路线图**（1-2条组合路线），用 mermaid flowchart 表达一日行程时间轴，例如：

   ```mermaid
   flowchart LR
     A["08:30 出发"] --> B["09:30 景点A 游玩2h"] --> C["12:00 午餐"] --> D["14:00 景点B 游玩1.5h"]
   ```

4. **门票类场所错峰建议**：汇总第六步产出的错峰信息（若对比表已含错峰字段，此处可做补充说明或合并简写）。

5. **数据来源说明**：列出本次实际使用的数据源、是否有源本次不可达/受限、如受限用了什么替代源补齐。

## 硬性红线（不可删改）

- 不编造价格、开放时间、门票信息；无法交叉验证的内容如实标注为"单源信息"或"信息可能滞后"，不冒充已核验结论。
- 不将刷帖/软文内容作为推荐依据。
- 数据源不可达时如实说明，不用占位数据填坑。
- 对比表和路线图为必需产出，不可省略。
