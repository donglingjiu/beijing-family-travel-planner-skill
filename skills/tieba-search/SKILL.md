# 贴吧关键词内容检索

检索百度贴吧站内与指定关键词相关的帖子，返回可追溯信息（标题、发布时间、链接、摘要），供上层角色做多源交叉核验。

## 实现方式说明

贴吧站点通常对自动化抓取有较强限制（登录墙、反爬、动态加载），直接爬取不稳定。本技能采用「通过通用网页检索能力、限定 `site:tieba.baidu.com`」的方式获取内容，复用已验证可用的百度 AI 搜索（BDSE）接口，只是加上站点过滤条件，不是重新造一套独立的抓取链路。

这不是简单包一层 baidu-search：本技能固定了 `search_filter.match.site=["tieba.baidu.com"]`，并且对结果做了统一的可追溯字段整理（标题/发布时间/链接/摘要），返回结构里显式区分「查到内容」「查询成功但为空」「站点不可达」三种状态，方便调用方据此判断能不能采信、要不要标注替代源。

## 使用方法

```bash
python3 skills/tieba-search/scripts/search.py '{"keyword": "朝阳公园 遛娃 攻略"}'
```

### 参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| keyword | str | 是 | - | 检索关键词，建议带上场景词（如"遛娃""攻略""门票"）以提高相关性 |
| search_recency_filter | str | 否 | year | 时间范围：`week` / `month` / `semiyear` / `year` |
| top_k | int | 否 | 20 | 最多返回条数 |

### 环境变量

| 变量 | 说明 |
|---|---|
| BAIDU_API_KEY | 百度千帆 AI 搜索 API Key，与 baidu-search 技能共用同一凭证 |

## 返回结构

```json
{
  "status": "ok",
  "source": "tieba.baidu.com",
  "keyword": "朝阳公园 遛娃 攻略",
  "items": [
    {
      "title": "帖子标题",
      "url": "https://tieba.baidu.com/p/xxxxx",
      "publish_time": "2026-05-10",
      "snippet": "帖子摘要内容",
      "source": "tieba.baidu.com"
    }
  ],
  "reason": null
}
```

`status` 三种取值及调用方应对方式：

| status | 含义 | 调用方应如何处理 |
|---|---|---|
| ok | 成功检索到贴吧内容 | 正常纳入交叉核验，标注来源为"据贴吧 + 发布时间" |
| empty | 检索成功但本次无相关贴吧结果 | 不代表不可达，视为该关键词下贴吧无匹配信息，继续用其他来源覆盖该场所/话题 |
| unreachable | 该源本次不可达（无凭证、网络失败、接口报错等） | **禁止编造或用其他来源伪装成贴吧结果**；在"数据来源说明"段落如实标注"贴吧本次不可达"，并说明用了哪些替代源（本地宝/小红书/博客）补齐同一场所的信息 |

## 错误处理说明

- 缺少 `BAIDU_API_KEY`：返回 `unreachable`，`reason` 中说明缺少凭证。
- 网络请求异常（超时、连接失败、API 报错）：捕获异常，返回 `unreachable`，`reason` 中带上原始异常信息，脚本本身正常退出（exit 0），不中断调用方的整体流程。
- 参数缺失（如未传 `keyword`）：返回 `unreachable`，`reason` 说明参数缺失，脚本以非零退出码提示是调用方使用错误而非数据源问题。
- **红线**：任何异常路径下都不生成占位帖子标题/时间/链接去填充 `items`，宁可返回空列表 + 明确 `reason`。

## 与角色 instructions 的对接说明

北京亲子游攻略专家角色的 instructions 草案第二步「多源实时检索」中，贴吧检索能力对应本技能；第三步「交叉核验判据」中提到的"贴吧"来源类型即来自本技能返回的 `items[].source`；当 `status=unreachable` 时，角色须在第七步输出的"数据来源说明"段落中注明"贴吧本次不可达"，并说明该场所/话题信息实际依赖的替代来源（本地宝/小红书/博客）。
